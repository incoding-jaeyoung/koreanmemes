# Project: vfmania.com Globalization - Phase 2 (Post Body Translation)

## 1. 목표 (Goal)
게시글 본문(Content)에 대한 **On-Demand(지연) 번역 및 캐싱** 시스템을 구축합니다. 
모든 본문을 미리 번역하지 않고, 해당 언어의 유저가 게시글을 읽을 때만 번역하여 비용을 최적화합니다.

## 2. 핵심 전략: Lazy Translation & Caching
1.  **조회 시점 번역:** 사용자가 상세 페이지에 진입했을 때, 해당 언어의 번역본이 DB에 없으면 그때 Gemini API를 호출합니다.
2.  **영구 캐싱:** 한 번 번역된 본문은 `PostTranslation` 테이블의 `content` 필드에 저장하여 다음 요청부터는 API 호출 없이 즉시 반환합니다.
3.  **수정 시 무효화 (Invalidation):** 원본 게시글이 수정되면 기존의 모든 번역본을 삭제하여 데이터 일관성을 유지합니다.

---

## 3. 상세 구현 단계 (Step-by-Step)

### Step 1: Gemini 유틸리티 보강 (`lib/gemini.ts`)
**목표:** 긴 마크다운 본문을 안정적으로 번역하도록 함수를 확장합니다.

1.  `translateContent(text: string, targetLang: string)` 함수 추가.
2.  **System Instruction 보강:**
    - "당신은 마크다운 형식을 완벽하게 유지하는 번역기입니다."
    - "코드 블록(` ``` `), 이미지 태그(`![]()`), HTML 태그는 번역하지 말고 원문 그대로 유지하세요."
    - "게임 용어 사전(Phase 1 참조)을 엄격히 준수하세요."

### Step 2: 본문 번역 전용 API 또는 Server Action 생성
**목적:** 클라이언트에서 번역이 필요할 때 호출할 엔드포인트를 만듭니다.

1.  **로직 흐름:**
    - 클라이언트로부터 `postId`와 `targetLang`을 받음.
    - **Check DB:** `PostTranslation`에서 해당 언어의 `content`가 이미 존재하는지 확인.
    - **If Exists:** 즉시 반환.
    - **If Not Exists:** - Gemini API를 호출하여 본문 번역.
        - 결과를 `PostTranslation` 테이블의 해당 레코드에 `update`(또는 `upsert`)하여 `content` 필드에 저장.
        - 번역된 본문 반환.

### Step 3: 게시글 상세 페이지 UI 연동
**목적:** 사용자에게 번역된 본문을 자연스럽게 보여줍니다.

1.  사용자의 현재 언어 설정과 게시글의 원본 언어가 다를 경우 번역 로직 트리거.
2.  **UX 최적화:** - 번역본을 가져오는 동안 "AI가 번역 중입니다..."라는 로딩 상태를 보여줌.
    - 번역이 완료되면 원본 본문 대신 번역된 마크다운을 렌더링.
    - (선택 사항) 사용자가 원본을 보고 싶을 경우를 대비해 '원문 보기' 토글 버튼 추가.

### Step 4: 원본 수정 시 번역본 삭제 로직
**목적:** 글이 수정되었을 때 잘못된 번역이 남지 않도록 합니다.

1.  게시글 수정 API(`updatePost`)를 찾아 로직을 수정합니다.
2.  게시글의 `content`가 변경되어 업데이트될 때, 해당 `postId`와 연결된 모든 `PostTranslation` 데이터의 `content`를 `null`로 만들거나, 레코드 자체를 `deleteMany` 하십시오.

---

## 4. 주의 사항
- **마크다운 유지:** Gemini가 번역 중에 마크다운 문법(헤더, 볼드, 링크 등)을 파괴하지 않도록 프롬프트를 정교하게 다듬어야 합니다.
- **에러 핸들링:** API 할당량 초과나 네트워크 오류 시, 사용자에게 에러 메시지 대신 "원본 본문"을 보여주어 서비스 이용에 차질이 없게 하십시오.
