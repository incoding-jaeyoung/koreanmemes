# 대댓글 (Nested Replies) — 개발 및 UI 정리

> 다른 도구/에이전트가 구현 또는 개선할 때 참고할 수 있도록 현재 구조와 남은 작업을 정리한 문서입니다.

---

## 1. 현재 구현 상태 요약

- **DB**: `comments` 테이블에 `parent_id` 컬럼 사용. 대댓글은 `parent_id`에 부모 댓글 `id` 저장.
- **API**: 댓글 목록 조회(GET)는 평면 목록(`created_at` 오름차순), 작성(POST) 시 `parent_id` 전달·저장. 대댓글 작성 시 부모 댓글 작성자에게 알림 생성.
- **프론트**:
  - `CommentList`: 평면 목록을 받아 `parent_id` 기준으로 트리(`buildCommentTree`)로 만든 뒤, 루트 → 자식 순으로 재귀 렌더링.
  - `CommentItem`: `parent_id`가 있으면 들여쓰기(`pl-6 ml-1`), `CornerDownRight` 아이콘 표시. **최상위 댓글만** "답글" 버튼 노출 → 클릭 시 `CommentForm`에 `parentId` 넘겨 대댓글 작성.
  - `CommentForm`: `parentId`(optional) 받아 POST 시 `parent_id`로 전송.

즉, **1단계 대댓글(댓글 → 답글)** 까지는 동작하며, “누구에게 단 답글인지” 문구나 2단계 이상 중첩 등은 미구현/미정리 상태입니다.

---

## 2. DB 스키마 (참고)

- **테이블**: `comments`
- **대댓글 관련 컬럼**:
  - `parent_id` (UUID, nullable): 부모 댓글 `id`. `NULL`이면 최상위 댓글.
- 기존 컬럼: `id`, `post_id`, `author_id`, `author_name`, `content`, `created_at`, `updated_at` 등.
- `parent_id`가 아직 없다면 마이그레이션에서 추가:

```sql
ALTER TABLE comments
ADD COLUMN IF NOT EXISTS parent_id UUID REFERENCES comments(id) ON DELETE CASCADE;
CREATE INDEX IF NOT EXISTS idx_comments_parent_id ON comments(parent_id);
```

---

## 3. API 동작

### GET `/api/posts/[id]/comments`

- `post_id`로 해당 글의 댓글만 조회.
- 정렬: `created_at` 오름차순 (평면 목록).
- 응답 필드에 `parent_id` 포함. 프론트에서 트리 구성에 사용.

### POST `/api/posts/[id]/comments`

- Body: `{ content, parent_id?, author_name? }`
- `parent_id`가 있으면 대댓글로 저장.
- 대댓글인 경우, 부모 댓글의 `author_id`에게 알림 타입 `reply` 등으로 알림 생성(이미 구현된 로직 확인 가능).

---

## 4. 프론트엔드 구조

### 4.1 CommentList (`src/components/comments/CommentList.tsx`)

- `fetchComments`로 평면 댓글 목록 수신.
- `buildCommentTree(comments)`로 `parent_id` 기준 트리 생성:
  - `parent_id`가 없거나 부모가 없으면 `roots`.
  - 있으면 부모의 `children`에 push.
- `renderComments(commentTree)`로 루트부터 재귀 렌더링.
- **주의**: `renderComments` 안에서 `CommentItem`에 `onReply={() => {}}` 를 넘기고 있음. 실제 “답글” 열기는 `CommentItem` 내부 `showReplyForm`으로 처리되므로, “답글” 버튼은 동작하지만 `onReply` 콜백은 현재 미사용.

### 4.2 CommentItem (`src/components/comments/CommentItem.tsx`)

- **props**: `comment`, `currentUserId`, `currentUserRole`, `onReply`, `onRefresh`, `translatedContent`.
- **대댓글 표시**:
  - `comment.parent_id`가 있으면:
    - 래퍼: `pl-6 ml-1 mt-2 mb-3`
    - 아이콘: `CornerDownRight`
    - 본문 영역: `ml-6`
  - 없으면 일반 댓글 스타일.
- **답글 버튼**: `!comment.parent_id` 일 때만 "답글" 버튼 표시 → 즉, **최상위 댓글에만** 답글 작성 가능. 대댓글에는 답글 버튼 없음(2단계 답글 미지원).
- **답글 폼**: 클릭 시 `CommentForm`에 `postId={comment.post_id}`, `parentId={comment.id}`, `placeholder={@${comment.author_name}...}` 등 전달.

### 4.3 CommentForm (`src/components/comments/CommentForm.tsx`)

- `parentId` optional. POST 시 `body: { content, parent_id: parentId }` 로 전송.
- `isReply` 이면 스타일/레이아웃만 달리 할 수 있음(현재는 `placeholder` 등).

## 5. UI/UX 개선 제안 (다른 도구에서 진행 시 참고)

1. **대댓글에 “누구에게 단 답글인지” 표시**
   - 예: `@부모닉네임에게 단 답글` 한 줄을 대댓글 상단에 표시.
   - 부모 댓글의 `author_name`은 GET 응답에 포함되어 있지 않으므로, 다음 중 하나 필요:
     - API에서 댓글 목록에 `parent_author_name` 등 부모 작성자 정보 포함, 또는
     - 프론트에서 `commentMap[comment.parent_id].author_name` 처럼 트리/맵으로 보유한 뒤 표시.

2. **i18n**
   - 예: `Comments.replyTo` = "@{name}에게 단 답글" 형태로 키 추가 후, `CommentItem`에서 `parent_id`일 때 사용.

3. **2단계 이상 대댓글 (선택)**
   - 현재는 “댓글 → 대댓글” 1단계만 가능.
   - 2단계(대댓글의 답글)를 허용하려면:
     - `CommentItem`에서 `comment.parent_id` 여부와 무관하게 “답글” 버튼 노출(또는 정책에 따라 특정 깊이까지),
     - `CommentForm`은 계속 `parentId`만 넘기면 되고, DB/API는 이미 `parent_id`로만 계층을 구성하므로 추가 수정 최소.

4. **정렬**
   - 현재: 전체를 `created_at` 오름차순으로 가져와 트리만 구성. 따라서 “부모 바로 아래에 자식이 시간순으로 붙는” 형태.
   - 원하면 “대댓글은 부모 직후에만 모아서 보이게” 등 정렬 규칙을 API 또는 프론트에서 명확히 할 수 있음.
