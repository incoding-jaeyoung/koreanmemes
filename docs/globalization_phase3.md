# Project: vfmania.com Globalization - Phase 3 (Comment Batch Translation)

## 1. 목표 (Goal)
댓글 시스템에 대한 **지연(Lazy) 묶음(Batch) 번역** 및 캐싱 시스템을 구축합니다. 
수많은 댓글을 효율적으로 처리하여 API 비용을 최소화하고 유저에게 자연스러운 다국어 소통 환경을 제공합니다.

## 2. 핵심 전략 (Core Strategy)
1.  **증분 번역 (Incremental Translation):** 전체 댓글 중 해당 언어로 번역된 적이 없는 댓글만 골라내어 번역합니다.
2.  **묶음 처리 (Batching):** 여러 개의 댓글을 하나의 Gemini API 요청으로 처리하여 토큰 효율을 극대화합니다.
3.  **뷰포트 감지 (Intersection Observer):** 사용자가 스크롤하여 실제 화면에 보이는 댓글들만 번역 트리거를 작동시킵니다.
4.  **지연 실행 (Debouncing):** 사용자가 빠르게 스크롤할 때는 요청을 보내지 않고, 특정 영역에 멈췄을 때만 번역을 수행합니다.

---

## 3. 상세 구현 단계 (Step-by-Step)

### Step 1: Gemini 유틸리티 확장 (`lib/gemini.ts`)
**목표:** 배열 형태의 텍스트를 한 번에 번역하는 함수를 추가합니다.

1.  `translateComments(comments: {id: string, text: string}[], targetLang: string)` 함수 구현.
2.  **프롬프트 설정:**
    - "입력된 JSON 배열의 각 텍스트를 번역하되, 형식을 엄격히 유지하여 JSON 배열로 응답하라."
    - "격투 게임 특유의 짧은 말투와 은어를 자연스럽게 살려라."
    - "이미지 이모티콘이나 특수문자는 보존하라."

### Step 2: 댓글 묶음 번역 API 생성
**목적:** 클라이언트에서 보낸 여러 댓글 ID를 처리합니다.

1.  **로직 흐름:**
    - `commentIds` 배열과 `targetLang`을 수신.
    - **DB 조회:** `CommentTranslation`에서 이미 번역된 데이터가 있는지 확인.
    - **필터링:** 번역본이 없는 원본 댓글들만 추출.
    - **AI 호출:** 번역이 필요한 댓글이 있을 경우만 Gemini API 호출.
    - **저장:** 새로 번역된 내용을 DB에 `createMany`로 저장.
    - **반환:** 기존 번역본과 신규 번역본을 합쳐서 클라이언트에 응답.

### Step 3: 프론트엔드 뷰포트 감지 및 최적화
**목적:** 효율적인 번역 트리거를 구현합니다.

1.  `Intersection Observer`를 활용하여 댓글 컴포넌트가 화면에 들어오는지 감지.
2.  **지연 로직:** 화면 진입 후 0.5초 이상 머물 경우에만 번역 요청 목록에 추가.
3.  **상태 관리:** 번역된 내용은 클라이언트 상태(또는 캐시)에 저장하여 불필요한 재요청 방지.

## 4. 구현 시 주의 사항
- **JSON 파싱 에러:** Gemini가 간혹 응답에 설명을 붙여 JSON 파싱이 깨지지 않도록 `response_mime_type: "application/json"` 설정을 활용하세요.
- **수정 대응:** 댓글 작성자가 내용을 수정하면 해당 댓글의 기존 번역본(`CommentTranslation`)을 삭제하는 로직을 댓글 수정 로직에 추가하세요.
