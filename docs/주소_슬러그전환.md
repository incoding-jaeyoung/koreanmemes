프로젝트 마이그레이션 지시서: UUID에서 영문 Slug(슬러그)로 전환

이 문서는 AI 개발 에이전트를 위한 가이드입니다. 현재 Next.js(App Router), Supabase, Vercel 환경에서 서비스 중인 커뮤니티 게시판의 URL 구조를 기존 UUID(/[id])에서 SEO 친화적인 영문 슬러그(/[english-slug])로 전환하는 작업을 수행하십시오.

📌 목표 및 요구사항

DB 업데이트: 기존 posts 테이블에 slug 컬럼을 추가하고 고유(Unique) 제약을 설정합니다.

슬러그 생성: 한글 제목을 영문으로 자동 번역 후 URL에 적합한 슬러그로 변환합니다.

라우팅 & SEO 보존: 기존 UUID 접속 시 검색 엔진 점수 보존을 위해 새 슬러그 주소로 301 영구 리다이렉트(permanentRedirect) 처리합니다.

마이그레이션: 기존에 작성된 게시글들의 슬러그를 일괄 업데이트하는 스크립트(API 라우트)를 작성합니다.

🛠 Step 1: 의존성 패키지 설치

터미널에서 다음 패키지들을 설치하십시오.

npm install slugify @vitalets/google-translate-api
npm install -D @types/slugify


🗄 Step 2: Supabase 데이터베이스 스키마 업데이트

Supabase SQL Editor에서 다음 쿼리를 실행하여 스키마를 업데이트하십시오.

-- 1. slug 컬럼 추가
ALTER TABLE posts ADD COLUMN slug TEXT;

-- 2. 중복 방지를 위한 UNIQUE 제약 조건 추가
ALTER TABLE posts ADD CONSTRAINT posts_slug_key UNIQUE (slug);

-- 3. 라우팅 조회 속도 향상을 위한 인덱스 생성
CREATE INDEX idx_posts_slug ON posts (slug);


⚙️ Step 3: 슬러그 생성 유틸리티 구현

lib/slug-utils.ts (또는 프로젝트 내 적절한 유틸리티 경로) 파일을 생성하고 아래 코드를 작성하십시오. 한글을 영어로 번역하고 특수문자를 제거합니다.

import slugify from 'slugify';
import { translate } from '@vitalets/google-translate-api';

/**
 * 한글 제목을 영문 슬러그로 변환합니다.
 * @param title 원본 한글 (또는 영문) 제목
 * @param id 중복 방지용 고유 ID (UUID의 앞 4~6자리 사용)
 */
export async function generateEnglishSlug(title: string, id: string): Promise<string> {
  try {
    // 1. 구글 번역 API를 사용하여 한글을 영어로 번역
    const { text: translatedText } = await translate(title, { to: 'en' });
    
    // 2. 특수문자 제거 및 소문자 하이픈 연결
    const baseSlug = slugify(translatedText, {
      lower: true,      // 소문자로 변환
      strict: true,     // URL에 안전하지 않은 문자 제거
      trim: true,       // 앞뒤 공백 제거
    });

    // 3. 중복 방지를 위해 기존 ID의 첫 6자리를 접미사로 추가
    const uniqueSuffix = id.split('-')[0].substring(0, 6);
    return `${baseSlug}-${uniqueSuffix}`;
  } catch (error) {
    console.error("Slug generation failed (Translation API error):", error);
    // 번역 API 실패 시 폴백(Fallback) 슬러그
    const uniqueSuffix = id.split('-')[0];
    return `post-${uniqueSuffix}`;
  }
}


🔗 Step 4: 라우팅 및 301 리다이렉트 (Next.js App Router)

기존 app/board/[id]/page.tsx 폴더를 app/board/[slug]/page.tsx로 변경하십시오. UUID와 Slug를 모두 처리할 수 있는 하이브리드 로직을 구현합니다.

import { permanentRedirect } from 'next/navigation';
// 사용하는 환경에 맞게 Supabase 클라이언트 임포트 (예: @supabase/ssr 활용)
import { createClient } from '@/utils/supabase/server'; 

export default async function PostPage({ params }: { params: { slug: string } }) {
  const supabase = createClient();
  const identifier = params.slug;

  // 식별자가 기존 UUID 형식인지 정규식으로 확인
  const isUUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i.test(identifier);

  // 식별자가 UUID면 id 컬럼을, Slug면 slug 컬럼을 조회
  const { data: post, error } = await supabase
    .from('posts')
    .select('*')
    .or(isUUID ? `id.eq.${identifier}` : `slug.eq.${identifier}`)
    .single();

  if (error || !post) {
    return <div>게시글을 찾을 수 없습니다.</div>;
  }

  // 핵심 SEO 로직: UUID로 접근했는데 해당 글에 이미 슬러그가 있다면 301 영구 이동 처리
  if (isUUID && post.slug) {
    permanentRedirect(`/board/${post.slug}`);
  }

  return (
    <article>
      <h1>{post.title}</h1>
      {/* 본문 렌더링 영역 */}
      <p>{post.content}</p>
    </article>
  );
}


🚀 Step 5: 기존 데이터 일괄 마이그레이션 스크립트 작성

기존에 등록되어 slug가 null인 게시글들을 업데이트하기 위한 1회용 API 엔드포인트를 구축합니다.
app/api/migrate-slugs/route.ts에 다음 코드를 작성하십시오.

import { NextResponse } from 'next/server';
import { createClient } from '@/utils/supabase/server';
import { generateEnglishSlug } from '@/lib/slug-utils';

export async function POST(request: Request) {
  // 실제 서비스 환경에서는 관리자(Admin) 권한 체크 로직을 반드시 추가할 것
  const supabase = createClient();

  // slug가 없는 게시글 조회
  const { data: posts, error } = await supabase
    .from('posts')
    .select('id, title')
    .is('slug', null);

  if (error) {
    return NextResponse.json({ error: error.message }, { status: 500 });
  }

  if (!posts || posts.length === 0) {
    return NextResponse.json({ message: "마이그레이션이 필요한 게시글이 없습니다." });
  }

  let successCount = 0;

  for (const post of posts) {
    // 번역 API 호출 간격 확보(Rate Limit 방지)를 위해 약간의 지연 시간을 주는 것도 좋음
    const newSlug = await generateEnglishSlug(post.title, post.id);
    
    const { error: updateError } = await supabase
      .from('posts')
      .update({ slug: newSlug })
      .eq('id', post.id);

    if (!updateError) {
      successCount++;
    } else {
      console.error(`Update failed for post ${post.id}:`, updateError);
    }
  }

  return NextResponse.json({ 
    message: "마이그레이션 완료", 
    totalTarget: posts.length, 
    successCount: successCount 
  });
}

글 작성 로직(Server Action 등) 수정: 새 글이 DB에 INSERT 될 때, generateEnglishSlug 함수를 거쳐 slug 값도 함께 저장되도록 비즈니스 로직을 수정할 것.
